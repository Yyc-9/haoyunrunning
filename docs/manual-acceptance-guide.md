# 好運跑班網站人工驗收與使用指南

這份指南用來逐步驗證本輪修改。請先使用指定測試帳號或名稱帶有「測試」的資料，不要拿真實學員進行破壞性操作。

## 一、先確認網站版本

1. 開啟正式網站。
2. 在 Safari 重新整理一次。
3. 若仍看到舊文字，清除網站資料後重新登入。
4. 確認管理員課程資料與教練課程浮窗皆顯示 `UTC+8`。

## 二、管理員確認課程開始時間

1. 使用超級管理員登入。
2. 進入「季度管理」。
3. 選擇「課程資料」。
4. 選擇本季度與要檢查的班級。
5. 找到「簽到判定開始時間」。
6. 確認下方說明為「固定使用台灣時間（UTC+8）」。
7. 不需要修改時間；若確實要調整，輸入 `HH:mm` 後儲存。

預期結果：教練簽到仍依課前十五分鐘至課後十五分鐘判定，只有顯示名稱改為 `UTC+8`。

## 三、驗證課程報價與插班計費

### 開課前

1. 從「訓練課程」進入一個可報名班級。
2. 點擊課表課程卡，進入詳情後點擊「立即報名」。
3. 登入指定測試帳號。
4. 完成學員身分資料，但先不要送出最後的匯款資料。
5. 確認系統自動從第一堂計費，並顯示整季價格。

### 開課後

1. 選擇已開始的班級。
2. 確認系統要求選擇計費起始課次。
3. 選擇未來課次，確認堂數與金額同步減少。
4. 若申報已參加過上一堂，只能選最近一堂已結束課次。

預期結果：不能任意選更早的歷史課次；舊生、新生與有效推薦人的單堂費率依後台設定計算。

## 四、驗證學員請假與補課

1. 使用具有本季度課程資格的測試學員登入。
2. 進入「我的帳戶」或學員頁面的「點名記錄」。
3. 展開最近一堂尚未開始的課程。
4. 點擊「請假」。
5. 點擊「選擇補課」。
6. 查看可選清單。

預期結果：

- 只能為最近一堂尚未開始的課程請假。
- 停課課次不需要請假。
- 補課只能選原請假課次之後的課。
- 只能選本季度其他班級。
- 已開始、停課、額滿或超過季度結束日的課次不能選。
- 取消補課後可以重新選擇；課次開始後不能再取消。

## 五、驗證教練本人簽到

1. 使用教練測試帳號登入。
2. 進入教練工作台。
3. 在「我的授課日程」點擊最近一堂課。
4. 確認浮窗或手機底部浮層顯示課程、日期、地點、原定教練、實際授課教練與簽到開放時間。
5. 確認時間標示為 `UTC+8`。

時間規則：

- 尚未到課前十五分鐘：按鈕不可用，只顯示開放時間。
- 課前十五分鐘至開課時間：點擊後為「準時簽到」。
- 開課後十五分鐘內：點擊後為「遲到簽到」。
- 開課十五分鐘後未簽到：管理員看到「應到未簽到」。

不要為了測試而修改正式班級時間。完整簽到請在真實課次開放時間內進行，或另行建立測試課次。

## 六、驗證教練請假與代班

這一步需要原教練、代班教練與管理員三個角色：

1. 原教練開啟具體課次，填寫請假原因並提交。
2. 管理員進入「教練管理」中的「教練簽到、請假與代班」。
3. 管理員核准請假並指定代班教練。
4. 代班教練登入後接受邀請。
5. 管理員完成最終確認。
6. 代班教練在開放時間內完成本人簽到。
7. 代班教練進入學員課程點名，完成現場出席核實。

預期結果：

- 原定教練仍保留在歷史記錄中。
- 原教練核准請假後不能替本堂簽到，也不能進行學員出席核實。
- 代班未最終確認前沒有現場權限。
- 最終確認後，代班教練成為實際授課教練。
- 代班未簽到時顯示「代班未到」，不算原教練無故缺席。

## 七、驗證匯款與人工對帳

完整測試會產生報名與對帳記錄，建議由一名測試學員、一筆明確的小額真實銀行交易和一名財務人員共同完成。

1. 測試學員完成課程報名並提交金額與後五碼。
2. 學員開啟「匯款狀態」。
3. 確認狀態為「已回報，待人工核對」，不能直接顯示入帳。
4. 財務進入「銀行對帳」，解鎖財務權限。
5. 上傳銀行下載的 XLSX 或 CSV。
6. 確認系統以金額與後五碼尋找候選記錄。
7. 財務選擇正確記錄並確認。
8. 學員重新開啟匯款狀態。

預期結果：

- 唯一匹配且財務確認後顯示「已確認入帳」。
- 金額不同、相同後五碼多人使用或找不到流水時顯示需要處理。
- 已確認記錄不能由學員重新覆蓋。
- 測試結束後，管理員應保留稽核記錄，並按測試範圍清理測試報名；不要刪除真實銀行流水依據。

## 八、開發者自動檢查

如果需要在本機確認程式：

```bash
cd "/Users/yangyichen/Desktop/好运网站"
npm run check
```

預期依序通過：

1. 繁體中文檢查。
2. 核心業務自動化測試。
3. ESLint。
4. Next.js 完整 build。

每次推送 `main` 後，GitHub Actions 也會自動執行相同檢查。綠色勾號代表所有檢查通過；紅色叉號代表應先修復後再繼續發布。

## 九、發現問題時如何回報

請記錄以下資料：

- 使用角色：學員、教練、代班教練、管理員或財務。
- 頁面網址。
- 操作前狀態。
- 點擊了哪個按鈕。
- 預期結果與實際結果。
- 發生時間（UTC+8）。
- 桌面或手機型號。
- 截圖；不要包含完整銀行帳號、密碼或其他敏感資料。
