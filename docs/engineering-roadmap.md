# 好運跑班網站工程改善路線

## 第一階段：上線安全與基礎品質

目前已完成：

- 課程採銀行匯款、後五碼與人工核對，未啟用尚未接好的第三方金流。
- 匯款圖片與收款資料維持受保護流程，不放在公開頁面。
- 隱私權、課程條款、取消退費與電子發票說明已建立正式頁面。
- 公開網站使用繁體中文，並有自動字詞檢查。
- 圖片上傳支援裁切，避免不同尺寸直接破壞桌面與手機版面。
- `robots.txt`、`sitemap.xml` 與基礎 SEO 已建立。
- 核心業務自動化測試已在本輪補齊，不再只依賴人工點擊。

結論：第一階段已完成。後續若人工完整走過一次報名、匯款、對帳、請假、補課、教練請假與代班，屬於正式驗收，不是第一階段仍缺少的工程功能。

## 第二階段：可靠性與可維護性

本輪已開始並完成第一批：

1. **建立可測試的規則模組**
   - `course-pricing`：整季、插班、舊生、新生、推薦人與補繳計價。
   - `course-attendance`：最近一堂請假與本季度其他班級補課資格。
   - `payment-workflow`：後五碼回報、待人工核對、確認入帳與異常退回。
   - `coach-duty-policy`：課前十五分鐘、準時、遲到、未簽到、請假與代班未到。

2. **讓頁面、伺服器與測試共用規則**
   - 頁面只負責顯示和收集操作。
   - 路由負責驗證身份、權限與輸入。
   - 規則模組負責可重複計算的業務判斷。
   - Supabase 負責保存結果、RLS 與稽核資料。

3. **建立部署前品質閘門**
   - GitHub 每次推送 `main` 或建立 Pull Request，都執行繁體檢查、核心測試、lint 與完整 build。
   - 任一項失敗時，不應把該版本視為可正式發布。

4. **統一時間語言**
   - 內部仍使用標準 IANA 時區 `Asia/Taipei`，避免伺服器運算出錯。
   - 管理員與教練看到的文字統一顯示 `UTC+8`。

## 工程結構

目前採用以下介面與接縫：

```text
公開頁面／管理後台／教練工作台
            │
            ▼
Next.js 路由：身份、權限、輸入驗證
            │
            ▼
業務規則模組：計價、匯款、補課、教練簽到
            │
            ▼
Supabase Adapter：資料、RLS、稽核紀錄
```

這個結構的重點是：規則只維護一次。未來改費用、補課期限或簽到時間窗時，不需要同時修改多個頁面。

## 第二階段下一批建議

等待人工完整驗收後再進行：

- 針對報名、匯款與對帳建立瀏覽器端端到端測試。
- 將過大的管理員路由依「季度、課程、內容、商城、對帳」拆成較深的模組。
- 將大型管理頁面依資料讀取與編輯功能分區，降低單一檔案修改風險。
- 為正式部署增加關鍵路由健康檢查與錯誤通知。
- 把人工驗收中發現的真實例外情況加入回歸測試。

端到端測試會操作帳號與資料，因此應在這份人工驗收完成、測試資料清理方式確認後再開啟，避免誤寫正式學員資料。
