# 好運跑班：學員、教練、管理員操作流程

日期：2026-09-18。這是本次本地修改的操作說明，不代表已部署到正式網站。

## 一、報名與正式關聯

1. 學員登入並報名具體的季度、班級。
2. 學員依網站帳戶匯款，回報匯款資料；此時仍是待核對，不算正式進班。
3. 財務完成銀行核對，或超級管理員使用既有「確認入帳」操作。
4. 報名成為已確認入帳後，系統依該班的正式教練排課建立關係。教練不需要再輸入學員信箱綁定。
5. 一人報兩班，保留兩班對應教練；不是新班覆蓋舊班。購買商品與課程資格分開判斷。

管理員事先需確認：季度狀態、課次日期、開課時間、任課教練帳號與排課完整。報名信箱須與登入信箱一致。沒有匹配帳號或排課的資料不會猜測綁定對象。

技術上使用已入帳報名與正式排課的即時計算關係，不複製另一份容易過期的名單。歷史手動綁定資料未刪除，但不再作為正式授權依據。調整班級任課教練在季度管理處理，臨時代班在教練管理處理。

## 二、學員上課怎麼操作

1. 手機或電腦登入，進入「我的」→ 點名區域。
2. 選擇上課季度；預設優先顯示自己有已入帳資格、仍在開課的季度。
3. 找到當天的班級與課次，點「我已到場，簽到」。
4. 系統記錄本人、班級、日期、伺服器時間。重複按不會新增第二筆。
5. 教練現場點名後，顯示雙方核實結果。

目前採用的可調整預設：學員簽到在開課前 15 分鐘至開課後 15 分鐘開放，沿用教練既有時間窗；不是定位打卡，也不代表系統能單憑按鈕證明人在現場。停課、已請假、未入帳、封存季度不可自主簽到。

狀態解釋：

| 顯示 | 意思 |
|---|---|
| 雙方已確認 | 學員自己簽到，教練也確認到課 |
| 學員已簽到，待教練確認 | 只有學員紀錄 |
| 教練已確認，學員未簽到 | 教練看到本人，但學員未操作 |
| 紀錄不一致，待核對 | 學員簽到，但教練記為請假或其他狀態 |
| 尚未雙重確認 | 證據尚不齊全，不自動等於缺席 |

教練和管理員不會冒充學員補出一筆「自主簽到」。漏簽時可保留教練到課確認及備註，清楚區分事實。

## 三、星期二請假，星期三補課

1. 學員在原班最近一堂尚未開始的課程請假。
2. 選擇原課次之後、同季度內、未開始且有名額的其他班級及日期。
3. 安排成功後，星期三教練在「課程點名」選星期三班和接收日期；點「更新簽到與補課名單」即可看到學員。
4. 名單標示「補課學員」「原班」「原請假日期」。這次補課不會把學員永久轉班。
5. 學員在自己的原班請假卡片下，使用「補課簽到」區域签到；星期三教練獨立點名。
6. 兩份證據都到齊，補課顯示完成。原班仍是請假，另外顯示補課已完成，不能改成原班到課。

取消、改期成功後，接收班更新名單時撤回原安排。補課已签到不得自行取消或改期；原班已签到也不得再建立請假。未保存的教練點名不會被手動更新名單覆蓋。

## 四、教練怎麼操作

- 工作台：辦理自己的上班簽到、請假、代班。
- 課程點名：查看自己獲授權班級／堂次的正式學員與補課學員，核對自主签到，逐一標記、填備註並儲存。
- 新補課、學員剛签到：先保存手上的點名，再按更新名單。
- 代班教練只獲得被安排堂次的點名權限；不因代一次班或接收一次補課而取得永久學員關係。

## 五、超級管理員怎麼操作

- 入帳：沿用季度報名中的確認入帳及財務銀行對帳流程。
- 班級教練配置：季度管理；教練本人到課與請假代班：教練管理。
- 學員與教練出勤對照：教練管理內「開啟課程出勤核對」，仍使用同一套課程點名頁，不新增後台獨立分頁。
- 帳號同時是管理員、教練和報名學員：也能打開自己的學員點名區，但只能以自己報名資格自主签到。
- 出勤有矛盾：查看兩份紀錄並記錄原因，不用一方紀錄覆蓋另一方。

## 六、驗證與上線順序

本地已做：新增前後 15 分鐘邊界測試、雙方／單方／矛盾狀態測試；用隔離 PostgreSQL 執行新迁移及 19 個資料庫情境。隔離測試只建立虛構資料，不連正式資料庫。工具用法參考 [PGlite 官方文件](https://pglite.dev/docs/)。

正式上線仍需：

1. 確認學員簽到的前後 15 分鐘預設是否符合營運習慣。
2. 檢查正式報名信箱、季度狀態與教練排課，確認歷史手動綁定不會是唯一尚未補齊的營運資料。
3. 備份並先套用 `20260918150000_formal_student_journey.sql`，再部署對應網站程式；不能只上傳程式而漏跑迁移。
4. 在不影響真實財務、名額與庫存的受控測試資料中，使用普通學員、普通教練、超級管理員完成桌面及手機驗收。
5. 驗收包含：未入帳拒絕、確認入帳後班級關聯、跨班拒絕、請假補課、接收名冊、雙重確認、取消改期、代班堂次權限、封存季度與多身份入口。

尚未完成的證據：本次沒有套用正式迁移、沒有推送部署、沒有用新版本完成真實帳號的線上寫入與手機觸控驗收。不能把本地測試通過寫成正式網站已全部通過。
