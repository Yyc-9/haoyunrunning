# 報名確認與教練資料驗收

## 核對結果

正式流程為：網站報名建立待人工核對記錄 → 超級管理員確認實際入帳，或財務銀行對帳確認 → 按課程設定的教練建立正式關係 → 教練查看已確認報名資料。

季度須處於招生或上課狀態；封存後移出目前教練名單。正式帳號型學員列表透過報名 email 與 profiles email 對應。尚未建立帳號者仍可出現在負責教練的報名資料頁。代課或跨班補課不自動取得其他課程的完整報名資料。

## 已修復

- 財務確認函數錯將 `approve_course_enrollment` 的 JSONB 回傳值賦給 composite row，導致 `malformed record literal`、整筆對帳回滾。改為直接保存 JSONB；已套用資料庫 migration，保留鎖定、名額限制、稽核與重複確認機制。
- 教練學員列表缺少報名表；兩個教練頁面現在可展開完整提交欄位，包括聯絡、LINE、緊急聯絡人、訓練目標、傷病、發票和同意資料。只映射明確欄位，不回傳內部 payload。
- 教練報名 API 原可讀未確認課程及所有活動報名。現在只讀目前負責且已確認的課程報名；普通教練不能修改正式報名狀態。
- 原先先截取全站最新 300 筆再篩教練，可能漏掉舊記錄。改為資料庫先限制教練、季度及確認狀態，再分頁讀取。
- 尚未排課日期時原不更新正式教練關係。現在歸屬與日期配置分離，換教練後也能回收原教練權限。
- 預設入口改為課程報名，CSV 補齊欄位並使用既有公式防護與前導零保存。

## 驗證

- 135 項自動測試通過，包含新欄位白名單、舊資料相容和超過 500 筆分頁測試。
- TypeScript、ESLint、繁體文字和生產構建通過。
- 真實 Supabase 臨時帳號 + 本地 HTTP：未登入、學生權限、待確認不可見、教練不可確認、管理員確認必填、重複確認、未排日期歸屬、完整資料、同一學員不同班隔離、財務引擎確認、滿額原子回滾、活動隔離、直接 DB 權限、換教練、封存檢查通過。
- 財務帳號授權以既有自動測試驗證，財務交易引擎以隔離合成交易實測；未登入真實財務同事帳號，也未發送郵件或產生真實付款。
- 真實教練登入後 Playwright 驗證兩個入口；1440px 與 390px 報名頁展開成功、無水平溢出，學員卡片可查看自己課程資料。截圖在 `output/playwright/coach-registration-20260920/`。
- 每次測試成功或失敗均清理；資料庫查核測試季度、報名、教練、auth 帳號、財務批次均為 0。

## 發布狀態

資料庫修復已套用。應用的 14 個修復檔案已整理，並在僅包含暫存內容的隔離目錄通過完整 `npm run check`。自動審批拒絕在預設 main 分支建立提交，要求使用者明確授權，因此應用尚未提交、推送或發布，正式網址驗收待授權後完成。

瀏覽器仍有既存的 CSP report-only 提示：`upgrade-insecure-requests` 在 report-only 模式不生效；本次沒有修改該全站政策，該提示未阻擋報名資料流程。
