# 財務課程／商城雙入口

使用者已確認獨立預覽並於 2026-10-31 授權「請推送」。本次僅發布財務雙入口，不包含已接受但明確暫不發布的點名第二版，也不包含原專案工作區其他未發布修改。

## 功能與權限

- `/finance` 顯示課程對帳、商城對帳；「我的」與帳戶選單文案同步。課程銀行明細匯入、季度與財務密碼沿用原功能。
- 商城頁提供每頁 25 筆、訂單月份（台北時區）、姓名／信箱／訂單／後五碼搜尋、匯款狀態篩選，以及商品、金額、收款帳戶、取貨班級與核帳歷史。
- 財務帳號和管理員皆需已登入並解鎖財務密碼。新 API 使用同一帳號綁定的財務 token；不增加財務帳號的管理員權限。
- 銀行匯款與舊人工核帳訂單可人工確認入帳或標記待補資料。需填寫依據；確認入帳另需勾選已核實實際入帳。
- 不提供本次未承諾的商城銀行檔案自動比對。標記補資料不自動寄信，財務仍需聯絡學員。
- 服務端從登入者推導操作人，資料庫核帳函數再檢查角色／已驗證財務信箱。RPC 與審計表禁止 anon/authenticated 直接存取。
- 資料庫鎖單並比較 updated_at，付款變更與審計原子保存；已入帳不可再次核帳，卡片付款及未保留庫存／無有效金額訂單不可人工核准。不改商品庫存或配貨狀態。

## 遷移與驗證

- 正式遷移：`20261031083905_finance_shop_review.sql`，先於應用發布執行。
- 應用測試 316/316 通過；隔離 PGlite 核帳回歸 10 組通過。覆蓋帳號權限、資料驗證、後五碼搜尋、月份邊界、並行衝突、重複核帳、庫存、審計原子性與伺服器限定權限。
- 正式資料庫 rollback 交易使用虛構訂單驗證核帳和審計，回滾後真實訂單仍 18 筆、審計 0 筆、無測試訂單殘留。
- 實際 React 元件使用本機虛構資料驗證桌面／390px 手機顯示、金額分轉元、前導零後五碼、確認入帳雙重檢查、保存回饋與已入帳只讀。臨時測試路由和公開內容測試檔已移除，不隨發布。
- 未代替真實財務人員登入、輸入財務密碼或確認任何真實款項。

SQL 回歸命令：`PGLITE_MODULE=<隔離 PGlite 模組路徑> node scripts/test-finance-shop-sql.mjs`。
