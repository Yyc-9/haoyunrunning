# 商品尺寸庫存

後台商品編輯新增「按尺寸管理庫存」，提供 XS、S、M、L、XL、2XL、3XL 及自訂尺碼。開啟後每個可選尺寸分別填現貨數量，總庫存自動加總。舊商品保留原有總庫存模式，不自動分配庫存，也不變更上架或預購狀態。

## 營運方式

1. 預購期間開啟「預購」。各尺寸即使現貨為 0 仍可下單，預購訂單不扣現貨。
2. 到貨後，先扣除要交付既有預購訂單的數量，再把各尺寸剩餘現貨填入庫存欄位。
3. 關閉「預購」，保持「上架」，儲存後同一商品頁繼續販售。售完的尺寸不能購買，其他尺寸不受影響。
4. 同一商品的不同款式、顏色和其他規格共用對應尺寸的庫存；本次未增加款式與尺寸交叉的庫存管理。

## 資料與訂單

- `shop_products.stock_by_size` 為可空 JSONB。NULL 表示舊總庫存模式；物件則對應可選尺寸與非負整數現貨。
- 資料庫觸發器檢查尺寸鍵、數量與總量上限，並重新計算 `stock_quantity`，防止前端偽造總數。
- 建立訂單以商品列鎖及條件更新扣除選定尺寸，整筆交易失敗會回滾。不同款式或規格的同尺寸明細不能重複使用庫存。
- 取消與付款逾時以訂單原有的 `size` 及 `is_preorder` 快照退還庫存。預購明細不回補現貨；重複釋放不重複回補。
- 庫存模式改變時，退回目前的總庫存或對應尺寸。仍有可取消之現貨訂單的尺寸不能移除，避免失去回補位置。有庫存的尺寸需先確認並歸零儲存才能移除。
- 舊 `create_shop_order_with_stock` RPC 轉呼叫同一套尺寸與規格驗證，避免繞過尺寸庫存。RPC 均維持 invoker，對外角色無執行權限。
