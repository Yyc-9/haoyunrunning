## 修復與新增

1. 儲存某個內容區塊後，不再覆蓋其他區塊未儲存的內容。共享圖片設定按欄位合併刷新；清單草稿不按索引錯誤拼接。
2. 同一頁面的文字和圖片由一個請求、一次資料庫 upsert 發布。第二個區塊驗證失敗時，第一個區塊也不寫入。
3. 後台避免並發重複提交；已儲存但重新讀取失敗時明確提示，不假稱已刷新。
4. 開班提醒可以清空；未設定的舊資料仍保留原預設值。
5. 0 元價格可正確保存。不存在的日期、負數、小數金額及無效規則被拒絕，不會靜默替換成預設值。
6. 新增「全期收費截止堂次」並連接實際報價。舊資料的該欄位原先未被使用；只有明確儲存新設定才啟用新規則，既有報價行為維持不變。按新規則收整季費用時，計費課次仍從選定起始堂次開始。
7. 新增「對外匯款資料」：銀行、三位銀行代碼、帳號、可選二維碼網址、發布預覽、核對後發布、重新讀取、版本衝突保護。桌面與手機皆可操作。更換銀行資訊會清除舊二維碼，舊預設二維碼不能搭配新帳號。
8. 內容中心和對外收款設定增加未儲存狀態與離開工作區/關閉頁面保護。

## 驗證方法與界線

- 單元與路由合約測試直接執行實際正規化、報價與路由程式，覆蓋原子發布、草稿合併、收款權限、版本衝突、故障拒絕舊帳號回退、課程/商城共用輸出。
- `scripts/verify-admin-controls.mjs` 使用臨時帳號、非當期且不公開的季度/課程、下架商品，實測 API 寫入、資料庫回讀、管理員回顯、前台隔離、封存限制；成功或失敗皆清理帳號、會話和測試資料。
- 全站文案及銀行帳號不替換成測試文字/測試帳號。跨區塊草稿瀏覽器驗收攔截寫入請求；真正的內容發布路由在記憶體資料庫替身中驗證原子性。正式資料庫的收款設定寫入在單一交易內測試並回滾。
- 新表 RLS 開啟，匿名及一般登入角色沒有直接讀寫權限，僅伺服器可寫。正式收款帳戶保持原值。
- Supabase advisor 的「RLS 無 policy」提示符合此伺服器專用表設計；另有既存的洩漏密碼保護未啟用提示，與本次內容控制無關，未變更 Auth 設定。
